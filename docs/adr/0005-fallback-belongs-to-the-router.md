# 回落是 router 的职责，不是 adapter 的

语音有四档引擎（`local` / `minimax` / `fish` / `mimo`），而「用哪一档、失败之后要不要换一档」
这件事**只住在一个地方**：`src/host/synth-registry.js` 里的 router。

规则（2026-10-03 定，来源是架构审查 candidate #1）：

```
minimax ──不可用/失败──▶ local      显式回落；失败原因照样留住
local   ──失败────────▶ （不回落）
fish    ──失败────────▶ （不回落）  用户明确选了这一档，换个声音比没声音更糟
mimo    ──未接线──────▶ （不回落）
```

**为什么上移**：老代码里这套编排压在 `minimax-voice.js` 一条 95 行的 if 链里，而
「回落到哪一档」这种规则散落其中时，加第五档要同时改分派、改原因拼接、还要记得
`cancel` 该转发给谁（老代码硬接 minimax，于是打断 `fish`/`local` 时在飞请求根本没被取消）。

**后果**：

- 加一档 = 写一个 adapter 工厂，**不用碰 router**；
- adapter 里**不许**写回落：它只回答两件事 —— 我现在能不能用、给我文本我给你音频；
- `available()` 是**活开关**（每次用之前重新问）：密钥可能刚填上、克隆可能刚被删。

反面教材就在 git 历史里：`synthUnit` 那条 if 链（第 2/4 笔退休，第 3/4 笔删除）。
