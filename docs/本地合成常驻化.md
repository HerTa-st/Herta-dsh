# 本地合成的常驻化 —— 每句 3 秒是怎么变成零点几秒的

> 状态：**已实施**（2026-09-28）。触发它的是一个直接的提问：「本地模型的出声能缩短吗」。
> 本文记的是**量出来的数**与**落地的东西**，不是设想。

## 1. 先量：3 秒到底花在哪

用一份临时探针（与 `lib/tts-worker.cjs` 同一套加载方式与 Kokoro 配置，区别是
**只加载一次、连合成多句**）在本机直接量：

| 阶段 | 耗时 |
|---|---|
| 进程启动 + 加载 addon | 0.02 – 0.66 s（看磁盘缓存） |
| **加载模型**（Kokoro + voices + 词典 + ruleFsts） | **2.64 – 3.67 s** |
| —— 冷启动合计（改造前每句都付一次） | 2.7 – 4.4 s |
| 加载完后**每句只付推理**：「嗯。」 | 0.22 – 0.28 s |
| 一句 15 字、3.5 s 音频 | 0.99 – 1.02 s |
| 39 字长句（9.1 s 音频） | 2.57 s（**RTF ≈ 0.28**） |
| 常驻进程内存 RSS | 加载后 249 MB，合成几句后 320 – 406 MB |

两条结论决定了做法：

1. **每句那 3 秒是模型加载，不是合成。**所以"常驻一次"就能把它整块省掉。
2. **RTF ≈ 0.28**：合成只要音频时长的 0.28 倍 —— 常驻之后她**念得比播放还快**，
   串行队列不会积压（3.5 s 的音频 1 s 就做完）。

顺带否掉一个直觉：`numThreads` **不是**杠杆。8 线程实测 0.30 RTF，比默认的
4 线程（0.28）还略差；换更小/可流式的模型是另一档工作（要新模型资产 + 改
`tts-release.js` 的 URL/体积/SHA pin），这一轮没做。

## 2. 落地：常驻进程 + 四条生死规则

`tts-worker.cjs` 多了 `mode: "serve"`：加载一次，之后 **stdin 一行一个请求、
stdout 一行一个应答**（`{id, op:"synth", text, out}` → 同一个 id 的应答）。
`src/host/tts-runtime.js` 管这个进程的生死，四条都是硬要求：

| 规则 | 为什么 |
|---|---|
| **懒启动** | 不在插件挂载时起进程。不用本地语音的人不该白占 ~250 MB —— 只有真的合成、或设置页切到「本地模型」时（`POST /herta-minimax-state {action:"warm"}`）才起 |
| **空闲回收** | `HERTA_TTS_IDLE_MS`（默认 **10 分钟**）没有请求就退掉，把内存还回去 |
| **崩溃/超时** | 进程死了或某条请求超时（默认 180 s），**所有在飞请求当场失败**而不是挂在半空；下一次请求重起一个新进程 |
| **卸载即杀** | 宿主卸载插件时调 `disposeLocalWorker()`。不挂这一条，热重载会在用户机器上留下 250 MB 的 node 孤儿 —— 而它只在有人用过本地合成时才存在，最难被发现 |

**退路**：常驻这条路起不来（脚本缺失 / spawn 报错 / ready 超时）时自动退回
一次性模式（每句一个进程）。慢，但那一句仍然会被说出来 —— 加速不该以"有时哑掉"为代价。

**为什么仍是子进程**：`tts-worker.cjs` 文件头那三条理由（sherpa 的 espeak 构建
吃不下非 ASCII 绝对路径 / `generate()` 同步阻塞 / 原生件崩溃隔离）在常驻模式下
一条都没变，反而更满足 —— 崩的是它自己，父侧重起即可。

## 3. 界面上的话必须跟着改

- 引擎行下多了一项事实：`合成进程：已预热 / 启动中… / 未启动（首次合成就地加载，约 3 秒）`
  （数据来自宿主快照的 `localWorker` 字段，只读查询**不会**把进程叫起来）。
- 「切到本地模型」会顺手发 `warm` —— 那 ~3 秒落在用户还在选的这几秒里，
  而不是落在他第一次真的想听的那一刻。
- `ENGINE_NOTES.local` 的措辞从「每句约 3 秒起」改成「常驻；首次或空闲回收后约 3 秒」。

## 4. 验证

- `scripts/test-tts-resident.mjs`（新增，进 `npm test`）：用一份**行协议一致的假 worker**
  把上面四条规则逐条钉住 —— 复用（第二次不再起进程）、空闲回收、请求超时、
  崩溃重启、ready 超时退路、模型缺失不起进程、预热幂等、卸载即杀。
  39 项，零依赖、无网络、不碰原生件。
- `scripts/test-tts-runtime.mjs`（真模型，环境变量开启）：真机冷热对比。
  本机实测（两次运行）：**冷 4.2 – 5.1 s（其中模型加载 2.6 – 2.8 s）→ 热 1.0 – 1.3 s**；
  试听台词热的 **1.0 – 1.1 s**（改造前是 4.25 s）。
- `scripts/test-minimax-voice-route.mjs`：多了 `warm` 动作与快照 `localWorker` 的断言，
  并在收尾显式 `disposeLocalWorker()`（不留孤儿）。

## 5. 测试/运维旋钮

| 环境变量 | 作用 | 真机是否该设 |
|---|---|---|
| `HERTA_TTS_IDLE_MS` | 空闲回收时间（默认 600000） | 不用设；想"一直热着"可以设很大 |
| `HERTA_TTS_SYNTH_TIMEOUT_MS` | 单条合成超时（默认 180000） | 不用设 |
| `HERTA_TTS_READY_TIMEOUT_MS` | 等 ready 的超时（默认 120000） | 不用设 |
| `HERTA_TTS_WORKER` | 换掉 worker 脚本 | **只在测试里**（假 worker） |
